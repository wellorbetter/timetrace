# TimeTrace 云端产品规划（个人数据云）

> 服务器：datanode1（2核 / 4GB / 60GB，124.221.201.53）
> 定位：**个人数据云** —— 桌面统计 + 网页日记/图库 + 多设备同步，自托管隐私可控。

---

## 一、为什么做（价值判断）

| 现状（纯本地）| 痛点 | 云端解决 |
|---|---|---|
| 统计只在桌面看 | 手机/其他电脑看不到 | Web 仪表盘 |
| 日记只能在电脑写 | 躺床上/路上想记没法记 | 手机浏览器写日记 |
| 图片本地存 | 换机/硬盘坏=丢 | 云端备份（图片/日记）|
| 单机数据 | 无法回溯/迁移 | 加密同步 + 导出 |

**核心叙事：一个属于你自己的隐私数据云。** 数据永远在自己的服务器，不经过任何第三方。

---

## 二、产品形态（分期）

### Phase 1：日记/图库 Web（先做 —— 你最初想要的就是图库）
- **Web 日记**：浏览器写日记（Markdown），手机可用
- **图库**：图片上传/相册式浏览（呼应"日记最开始想当图库"）
- **日历视图**：Web 日历看哪天有日记/图片（复用桌面端体验）
- **数据入口**：桌面端日记/图片 → 同步到云；Web 可增改删

### Phase 2：统计云端 + Web 仪表盘
- 桌面端上传 usage 数据（按天批量，加密）
- Web 看：应用分布 / 日周月汇总 / 热力图 / 趋势
- 图表与桌面端一致（fl_chart → Web 用 ECharts/轻量图库）

### Phase 3：同步协议 + 后台管理
- 双向同步（桌面↔云，冲突合并：按条目时间戳）
- 管理后台：设备列表、存储用量、导出/清空、账号、删除数据
- 移动端 PWA（手机装到主屏，接近原生体验）

---

## 三、技术选型（2核4GB 够用）

| 层 | 方案 | 理由 |
|---|---|---|
| 后端 | **Rust axum**（或 actix-web）| 与桌面核心同语言，可复用 crates/core 的聚合逻辑；低内存 |
| 存储 | **SQLite**（WAL）| 单机够用（个人数据量小），零运维 |
| 图片存储 | 本地磁盘目录 + DB 记录路径 | 60GB 足够；后续可接 OSS |
| 认证 | 简单 JWT + 密码（自托管单人）| 轻量 |
| 前端 | **Vue3 + Vite**（或 Next.js）| 日历/图库组件生态好；单页面 |
| 部署 | docker-compose 或 systemd + 反向代理（nginx/caddy）| 4GB 机器轻松 |

**为什么不选重方案**：单人自用，Postgres/Redis/K8s 都是过度设计。SQLite + axum + Vue 足够支撑 10 年数据量。

## 四、核心 API 设计（草案）

```
POST /api/auth/login                # 登录
GET  /api/calendar?month=2026-08    # 月视图（日记/图片/统计标记）
GET  /api/diary?date=2026-08-06     # 某天日记列表
POST /api/diary                     # 新建日记（Markdown）
PUT  /api/diary/:id                 # 编辑
DELETE /api/diary/:id               # 删除
POST /api/diary/:id/images          # 上传图片（multipart）
GET  /api/images?date=...           # 图库查询
POST /api/sync/stats                # 桌面端批量上传 usage（按天）
GET  /api/stats/summary?range=week  # Web 统计
GET  /api/admin/summary             # 后台：存储/设备/条目数
POST /api/admin/export              # 导出全量
```

## 五、与桌面端的关系

```
┌─ 桌面端（已有）─────────────┐   ┌─ 云端（新建）──────────────┐
│ Rust 监控 + SQLite          │   │ axum API + SQLite          │
│ 统计/日记/图库（本地优先）   │──▶│ 日记/图库 Web + 统计看板    │
└────────────────────────────┘   │ 后台管理 + 同步             │
        ▲                        └────────────────────────────┘
        │ 同步（加密、增量、冲突合并）
        └─────────────────────────────────────────────────────
```

**原则：本地优先（local-first）** —— 桌面端离线完全可用；云是备份 + 多端入口，不是必需。

---

## 六、建议路径（务实）

1. **本周**：axum 骨架 + 登录 + 日记 CRUD + 图片上传（Web 记日记能用了）
2. **下周**：日历视图 + 图库相册页（Web 端完整日记/图库体验）
3. **再下周**：统计同步 + Web 看板 + 管理后台
4. **最后**：桌面端同步客户端（对接上传）+ PWA

> 建议先把 Phase 1（日记/图库 Web）做出来 —— 你 80% 的日常需求（记备忘录、看图）立刻能用，统计同步不着急。

---

## 七、要不要"后台管理系统"？

**要，但是轻量的**（不是重后台）：
- 单人自用 → 一个 `/admin` 页面：存储用量、条目统计、导出、清除、设备管理
- 不需要用户系统/角色权限/审计 —— 单人没必要
- 复用了 Web 前端，成本低
